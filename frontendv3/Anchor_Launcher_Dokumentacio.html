1. Bevezetés, a téma ismertetése, témaválasztás indoklása, szakmai célkitűzés

Az Anchor Launcher (korábbi nevén Wreck Launcher, Flagship Launcher) egy modern asztali játékindító alkalmazás, amelyet Electron, React és Node.js technológiák felhasználásával készítettem. A program célja, hogy egyetlen egységes felületről biztosítson hozzáférést a felhasználó különböző platformokon (Steam, GOG, itch.io) található játékaihoz, valamint lehetővé tegye a torrent-alapú játékletöltést alternatív forrásokból (FitGirl, Dodi Repacks, Byxatab, Online-Fix, PC Games Torrent).

Témaválasztás indoklása: Napjainkban egy átlagos játékos többféle platformon is rendelkezhet játékokkal – a Steamen, GOG-on, itch.io-n, illetve akár kalózforrásokból is. Ezek kezelése külön-külön alkalmazásokban történik, ami kényelmetlen és széttöredezett élményt nyújt. Az Anchor Launcher ezt a problémát orvosolja azáltal, hogy egyesíti az összes játékplatformot egyetlen, letisztult felületen, miközben a torrent-alapú letöltéseket is natívan támogatja.

Szakmai célkitűzés: A projekt elkészítése során célom volt, hogy egy olyan valóságban is használható, teljes értékű asztali alkalmazást hozzak létre, amely:

  • modern, reszponzív felhasználói felülettel rendelkezik (Tailwind CSS + React);
  • Electron segítségével natív asztali alkalmazásként fut Windows rendszeren;
  • támogatja a Steam, GOG és itch.io játékok böngészését, részletes adatainak lekérését;
  • integrált torrent-klienst tartalmaz (WebTorrent) a játékok letöltéséhez;
  • felhasználói fiókrendszert biztosít regisztrációval, bejelentkezéssel, ismerősök kezelésével;
  • testreszabható beállításokkal rendelkezik (téma, országkód, megjelenés).

2.2 Adatszerkezet bemutatása

Az Anchor Launcher adatkezelése két rétegben valósul meg:

  1. Helyi (lokális) adattárolás: localStorage, valamint az Electron main processben tárolt JSON fájlok a userData mappában.
  2. Távoli (backend) adatbázis: A program egy Node.js/Express backenddel kommunikál REST API-n keresztül, amely egy SQLite/PostgreSQL adatbázist használ.

A main process egy torrent-cache rendszert használ – a kulcs-érték párokat JSON fájlban tárolja a userData/torrent-cache.json fájlban. A következő cache-kulcsok használatosak:

  • downloads:resume – a folytatandó letöltések listája
  • downloads:completed – a befejezett letöltések listája

Backend API végpontok (a preload.js által elérhető IPC csatornák)

A program a következő főbb adatkategóriákat kezeli a backend segítségével:

  • Felhasználók: regisztráció, bejelentkezés, profilkezelés, token-kezelés
  • Ismerősök: hozzáadás, eltávolítás, keresés, lista
  • Platformok: Steam, GOG, itch.io fiókok összekapcsolása, játékok listázása
  • Játékok (backend): játékok listázása, keresése, részletes adatok lekérése, árinformációk
  • Beállítások: felhasználói beállítások tárolása (téma, országkód, platform kapcsolatok)
  • Speciális akciók: akciós, kiemelt, közelgő játékok listázása

A renderer folyamat (React) soha nem fér közvetlenül a backendhez vagy a fájlrendszerhez. Minden kommunikáció az Electron IPC (Inter-Process Communication) rétegen keresztül történik, a contextBridge által biztonságosan exponált API-n keresztül. A main processben található kontrollerek végzik a tényleges HTTP-kéréseket a backend felé, valamint a lokális fájlrendszerrel és a Steam/GOG/itch.io API-kkal való kommunikációt.

2.3 Algoritmusok bemutatása

A program során számos érdekes algoritmus és logikai megoldás valósult meg. Az alábbiakban az 5 legjellemzőbbet mutatom be.

2.3.1 Token-kezelés és autentikáció (preload.js)

A hitelesítési rendszer többlépcsős token-kezelést valósít meg. A resolveAuthToken() függvény először a localStorage-ból próbálja kiolvasni a tokent, majd sikertelenség esetén IPC-n keresztül a main process-től kéri le. A token expirációját a main process jelzi a renderer felé a auth:token-cleared eseményen keresztül, amelyre a renderer egy wreck:auth-expired egyedi eseményt bocsát ki. Az App.jsx-ben erre az eseményre feliratkozó AuthExpiredGuard komponens automatikusan a login oldalra irányítja a felhasználót.

// Token lekérés logikája (preload.js)
async function resolveAuthToken() {
  const local = getAuthToken();       // 1. localStorage
  if (local) return local;
  
  const fetched = await invokeWithTokenSync('user:get-token');  // 2. IPC
  return typeof fetched === 'string' && fetched.trim() 
    ? fetched.trim() : null;
}

2.3.2 Végtelen hurok a kiemelt játékok karusszeljében (GameSliderBase.jsx)

A kiemelt (featured/discounted/upcoming) játékok karusszelje végtelen hurokban működik. A useProceduralLoop logika stream-ordinális számokat használ, és amikor a felhasználó a karusszel széléhez ér, új elemeket "gyárt" a mögöttes adatokból, miközben a túl távoli elemeket levágja. Ez biztosítja, hogy a felhasználó soha ne érjen a lista végére.

// Stream-alapú végtelen loop (rövidítve)
if (nextIndex <= extendThreshold) {
  // Új elemek beszúrása az elejére
  const prepend = Array.from({ length: baseLen }, (_, offset) => 
    createProceduralEntry(firstOrdinal - baseLen + offset));
  nextCards = [...prepend, ...nextCards];
  nextIndex += prepend.length;
}
// Távoli elemek levágása a memória hatékony kezeléséért
if (sliceStart > 0 || sliceEnd < nextCards.length) {
  nextCards = nextCards.slice(sliceStart, sliceEnd);
  nextIndex -= sliceStart;
}

2.3.3 Regisztráció e-mail validáció (Login.jsx)

A regisztráció során a program ellenőrzi, hogy a felhasználónév és a jelszó mezők nincsenek-e üresen hagyva, valamint hogy regisztráció esetén az e-mail mező is ki van-e töltve. Maga a backend végzi a validációt, de a frontend is megelőző ellenőrzéseket végez, hogy minél előbb visszajelzést adjon a felhasználónak:

// Validáció a regisztrációs űrlap elküldése előtt
if (!username || !password) {
  setStatus('Please enter username and password');
  return;
}
if (isRegisterMode && !email) {
  setStatus('Please enter your email');
  return;
}
// A backend ellenőrzi a duplikált felhasználónevet is
if (token && typeof token === 'string' && token.trim().length > 0) {
  // Sikeres regisztráció
} else {
  setStatus('Registration failed. Username may already exist.');
}

2.3.4 Torrent letöltéskezelés és állapotmegőrzés (DownloadManagerContext.jsx)

A letöltéskezelő kontextus a WebTorrent kliens köré épül, és három rétegű állapotmegőrzést valósít meg:

  1. Memória (React state): az aktuális munkamenet letöltései
  2. localStorage: a letöltések folytatható állapota (magnet URI + elérési út)
  3. Electron cache (userData): a letöltések tartós állapota a main processben

A restoreInterruptedDownloads függvény a program indulásakor automatikusan újraindítja a korábban megszakadt letöltéseket (1,8 másodperces késleltetéssel a stabil indulás érdekében). A mergeArtworkFields algoritmus biztosítja, hogy a letöltésekhez tartozó borítókép megőrződjön.

2.3.5 Országkód feloldási lánc (preload.js)

A Steam és GOG árinformációk lekéréséhez országkódra van szükség. A resolvePreferredCountryCode függvény egy több lépcsős feloldási láncot használ:

async function resolvePreferredCountryCode(preferred) {
  // 1. Direkt paraméter
  if (direct) return direct;
  // 2. Cache (30 sec TTL)
  if (cachedCountryCode && now < cachedCountryCodeExpiresAt) 
    return cachedCountryCode;
  // 3. Backend beállítások (store, display, account)
  // 4. Böngésző lokáció (Intl locale)
  // 5. Alapértelmezett: 'DE'
  return 'DE';
}

2.5 Fejlesztési lehetőségek

Az Anchor Launcher számos további fejlesztési lehetőséget kínál. Az alábbi funkciók megvalósítását tervezem a későbbiekben:

  1. Epic Games Store integráció: Az Epic Games Store egyre népszerűbb, és a havi ingyenes játékai miatt sokan használják. Az API integrációja tovább bővítené a platformtámogatást.
  2. Ubisoft Connect / EA App integráció: A nagy kiadók saját platformjainak támogatása tovább növelné az alkalmazás lefedettségét.
  3. Játék telepítés/menedzsment: A jelenlegi verzió csak a Steam játékok listázását és indítását támogatja. A jövőben a GOG és itch.io játékok teljes körű telepítését és frissítését is támogatni szeretném.
  4. Beépített kereső és szűrő (műfaj, ár, platform): Bár a program már rendelkezik alapvető szűrőkkel, a tervek szerint egy komplex, több szempontú keresőfeületet kapna (cím, műfaj, ár, kiadó, megjelenés éve alapján).
  5. Felhőalapú játékmentések szinkronizálása: A Steam Cloud-hoz hasonló funkció, amely lehetővé teszi a játékmentések biztonsági mentését és szinkronizálását.
  6. Játékstatisztikák és játékidő-követés: Részletes statisztikák a játékokkal töltött időről, grafikonokkal és összehasonlításokkal.
  7. Többnyelvű felület: A jelenleg angol nyelvű felület bővítése további nyelvekkel (magyar, német, spanyol, francia, stb.) az i18n könyvtár segítségével.
  8. Linux támogatás: Bár az alkalmazás Electron alapú, jelenleg csak Windowsra készül telepítő. A Linux verzió elkészítése (AppImage/Flatpak) szélesítené a felhasználói bázist.
  9. Beépített játékszerkesztő/mod menedzser: Lehetőség a játékok modjainak böngészésére és telepítésére (pl. Nexus Mods integráció).
  10. Saját játékbolt (Anchor Store): Hosszú távú cél egy saját digitális játékbolt létrehozása, ahol a fejlesztők közvetlenül árulhatják játékaikat.

4. Összefoglalás, köszönetnyilvánítás

+ +

Az Anchor Launcher projekt célja egy olyan univerzális játékindító alkalmazás létrehozása volt, amely egyesíti a különböző platformok játékainak kezelését, és ezzel kényelmesebbé teszi a felhasználók számára a játékaik elérését. Visszatekintve a fejlesztési folyamatra, úgy érzem, hogy a kezdeti szakmai célkitűzéseket sikerült megvalósítanom.

+ +

Sikerült megvalósítani:

+
    +
  • Egy modern, reszponzív felhasználói felületet Tailwind CSS és React segítségével, amely sötét témával és letisztult dizájnnal rendelkezik.
    • +
  • Teljes körű felhasználókezelést (regisztráció, bejelentkezés, JWT token alapú autentikáció, token lejárat kezelés).
    • +
  • Többplatformos (Steam, GOG, itch.io) játékböngészést és részletes adatlapok megjelenítését.
    • +
  • Beépített torrent-klienst WebTorrent segítségével, a letöltések automatikus folytatásának lehetőségével.
    • +
  • Ismerősök kezelését és közös játékok megjelenítését.
    • +
  • Testreszabható beállításokat (téma, országkód).
    • +
  • Speciális karusszel nézetet a kiemelt, akciós és közelgő játékok számára, végtelen loop algoritmussal.
    • +
+ +

Kihívások: A projekt során a legnagyobb kihívást az Electron IPC rendszerének mélyreható megismerése, a biztonságos contextBridge kialakítása, valamint a végtelen loop algoritmus implementálása jelentette a GameSliderBase karusszel komponensben. Utóbbi különösen érdekes feladat volt, mert a hagyományos klónozás helyett egy stream-alapú megközelítést alkalmaztam, amely hatékonyabb memóriakezelést tesz lehetővé. A torrent letöltéskezelés háromrétegű állapotmegőrzése (memória, localStorage, Electron cache) szintén komoly tervezést igényelt.

+ +

Tanulságok: A projekt során sokat tanultam az Electron alkalmazások felépítéséről, a React komponensek optimalizálásáról (useMemo, useCallback, useRef helyes alkalmazása), a Tailwind CSS utility-first szemléletéről, valamint a WebTorrent könyvtár használatáról. Emellett gyakorlatot szereztem a REST API tervezésében, az aszinkron adatlekérési mintákban, valamint a hibakezelés és a felhasználói élmény (UX) tervezésében.

+ +

További tervek: A programot a jövőben is szeretném fejleszteni. Elsősorban az Epic Games Store integrációját, a Linux támogatást és a többnyelvű felületet tervezem megvalósítani. Ezenkívül a letöltéskezelő további finomhangolása (sávszélesség-korlátozás, ütemezés) is szerepel a terveim között.

+ +

Köszönetnyilvánítás: Szeretném megköszönni mindazoknak, akik támogattak e projekt elkészítésében. Külön köszönettel tartozom családomnak, akik türelemmel viseltettek irántam a fejlesztés hosszú órái alatt. Köszönöm az ismerőseimnek, akik tesztelték a programot, és hasznos visszajelzésekkel segítették a munkámat. Végül, de nem utolsósorban köszönöm a Node.js, Electron, React és WebTorrent közösségeknek a kiváló dokumentációt és a nyílt forráskódú eszközöket, amelyek lehetővé tették ennek a projektnek a megvalósítását.
